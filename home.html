DRYHOLEWHITE PAPER

Status: working draft. Mechanics that are not finalized are described as concepts, not as fixed rules. No supply figures, reward formulas or contract addresses are stated here.

01What is DRYHOLE

DRYHOLE is an on-chain drilling protocol built around NFTs, Epochs and token utility.

The protocol is organized around a simple cycle: EPOCH → DRILL → TOKEN → STAKE → ETH. Every part of the system operates within the same recurring Epoch structure. 1 day = 1 Epoch.

The idea behind DRYHOLE is simple: drilling starts with an unknown outcome. The system provides the structure around that activity, while each Epoch creates a new cycle for participation.

02Epoch System

Time in DRYHOLE is divided into Epochs. One Epoch represents one day.

Epochs provide the shared rhythm for the protocol. Rather than treating each module as an isolated system, DRYHOLE uses the same Epoch cycle across its core activities. An Epoch begins, the protocol operates through its cycle, and when the Epoch ends, the current cycle settles before the next Epoch begins.

This creates a consistent reference point for:

  • Drilling activity
  • Token activity
  • Staking activity
  • Protocol settlement
  • Historical records

The Epoch system is intended to make activity easier to understand and reference across the protocol.

03NFT

NFTs are the drilling assets of DRYHOLE.

An NFT is not simply a collectible displayed in the Collection. It is intended to have a role within the protocol's drilling system. The NFT participates in DRILL, connecting the collectible layer with the protocol's utility layer.

The relationship can be represented as: NFT → DRILL → TOKEN.

The exact NFT mechanics, requirements and parameters will be defined as the system is finalized.

04Drill

DRILL is the core action of DRYHOLE. The drilling system uses NFTs as its primary drilling assets.

A drill takes place within the protocol's Epoch structure. The purpose of the drill is to participate in the system and produce token utility through the drilling process. The core relationship is: NFT → DRILL → TOKEN.

DRYHOLE uses the idea of drilling into the unknown as part of its protocol identity. The Cross Section represents this visually: the surface is known, while what lies beneath remains unknown until the system drills into it.

Specific drilling rates, limits, rewards and other parameters are not finalized in this draft.

05Token

The DRYHOLE token represents the utility layer of the protocol. It is connected directly to the drilling system.

Rather than treating the token as a separate asset with no relationship to the protocol, DRYHOLE is designed around the relationship: NFT → DRILL → TOKEN. The token then continues into the staking system: TOKEN → STAKE → ETH.

This gives the token a role beyond simply existing as a tradable asset.

Token supply, emission, distribution and other economic parameters are not finalized.

06Stake

STAKE provides utility for the DRYHOLE token. The basic relationship is: TOKEN → STAKE → ETH.

Users participate in the staking system using the DRYHOLE token, with ETH serving as the reward asset. The purpose of this system is to give the token a role within the broader DRYHOLE economy.

The exact staking parameters are not finalized. This includes:

  • Reward rate
  • ETH distribution
  • Staking duration
  • Limits
  • Settlement details
  • Other economic parameters

These will be documented when finalized.

07Swap

SWAP is the exchange layer of DRYHOLE. Its purpose is to provide a place where supported assets and tokens can be exchanged within the ecosystem.

SWAP is separate from DRILL and STAKE, but remains part of the same protocol environment.

The exact supported assets, routing, fees and implementation details are not finalized.

08Market

MARKET is the marketplace layer of DRYHOLE. It provides a place for DRYHOLE NFTs and other supported assets to be bought and sold.

The distinction between Collection and Market is intentional:

  • Collection. Explore the NFTs and assets that exist within DRYHOLE.
  • Market. Explore assets that are available for acquisition.

Listing rules, pricing, settlement and marketplace mechanics will be defined as the Market system is finalized.

09The DRYHOLE Economy

The DRYHOLE economy connects the protocol's major components. The intended relationship is:

NFT ↓ DRILL ↓ TOKEN ↓ STAKE ↓ ETH

Each layer has a different role:

  • NFTs provide the drilling asset.
  • DRILL connects NFTs to the protocol's token utility.
  • TOKEN provides the economic utility layer.
  • STAKE gives the token a role within an ETH reward system.
  • SWAP provides an exchange layer.
  • MARKET provides a marketplace for supported assets.

All of these systems operate around the same Epoch-based protocol structure.

10The Complete Cycle

A complete DRYHOLE cycle can be understood through the following sequence:

  • 1 day. One Epoch.
  • Epoch. The cycle opens.
  • Drill. NFT participates in the drilling system.
  • Token. Drilling connects to token utility.
  • Stake. Token participates in the staking system.
  • ETH. ETH is the reward asset.
  • Next Epoch. The cycle begins again.

The purpose of the Epoch system is to keep these activities within a shared protocol rhythm rather than treating them as unrelated features.

11Collection

The Collection is the public record of DRYHOLE NFTs. It provides a place to explore the assets associated with the protocol.

Collection and Market serve different purposes. Collection focuses on what exists. Market focuses on what is available. The Collection is therefore part of the discovery layer of DRYHOLE, while Market serves the exchange layer.

12Protocol Design

DRYHOLE is designed around a simple principle: every component should have a role.

  • NFTs are connected to DRILL.
  • DRILL is connected to TOKEN.
  • TOKEN is connected to STAKE.
  • STAKE connects to ETH.
  • SWAP and MARKET provide additional ways for assets and value to move within the ecosystem.

The Epoch system provides the common timing structure that connects these components. This keeps the protocol understandable while allowing individual modules to evolve independently.

13Parameters & Finalization

This White Paper intentionally does not establish economic parameters that have not yet been finalized. The following may be defined separately as development progresses:

  • Token supply
  • Token distribution
  • Emission
  • Drilling rate
  • Drilling rewards
  • Staking rewards
  • ETH distribution
  • Staking duration
  • Fees
  • Marketplace parameters
  • Swap parameters
  • Contract addresses

Until officially defined, these values should be treated as not finalized.
